# เกมจับคู่ตัวเลข V Square Clinic

เกมจับคู่ตัวเลขหน้าเดียว (React 19 + Vite 8 + TypeScript) สำหรับ V Square Clinic ใช้ที่บูธงานอีเวนต์บนจอสัมผัสแนวตั้งของเครื่อง Windows ผู้เล่นมีเวลา 25 วินาทีในการพลิกการ์ดบนกระดาน 7×6 เพื่อหาคู่เลข 48 เป็นแอป PWA จึงเล่นได้โดยไม่ต้องใช้อินเทอร์เน็ต หลังจากเปิดเกมครั้งแรกขณะมีอินเทอร์เน็ตหนึ่งครั้งด้วยเบราว์เซอร์และโปรไฟล์เดียวกับที่จะใช้เล่น (หน้าต่าง InPrivate และโหมด kiosk ของ Edge ไม่เก็บไฟล์ไว้หลังปิด ดู[คู่มือตั้งค่าเครื่อง](docs/kiosk-setup-windows.md))

## สิ่งที่ต้องมีก่อน build

- Node 26 (npm 11)
- ไฟล์ `fonts/gotham/Gotham-Medium.woff2` ไฟล์นี้ไม่อยู่ใน repository เพราะเป็นฟอนต์มีลิขสิทธิ์ ต้องขอจากเจ้าของงานแล้ววางไว้ที่พาธนี้ **ถ้าไม่มีไฟล์นี้ `npm run build` จะล้มเหลว**

## คำสั่ง

รันจากรากโปรเจกต์

```bash
npm install          # ติดตั้งแพ็กเกจ
npm run dev          # เปิดเซิร์ฟเวอร์สำหรับพัฒนา
npm test             # ชุดทดสอบ Vitest
npm run typecheck    # ตรวจชนิดข้อมูลด้วย TypeScript
npm run build        # สร้างเกมที่พร้อมนำขึ้นใช้งานในโฟลเดอร์ dist/
npm run preview      # เปิดดูเกมที่ build แล้ว
npm run e2e          # ทดสอบ Playwright: เล่นได้ขณะออฟไลน์ (offline.spec.ts) รีเซ็ตแล้วไม่เห็นตัวเลขของรอบใหม่ (reset.spec.ts) ฉากนับถอยหลังบังการแตะ (countdown.spec.ts) สีของข้อความหัว pop-up (popup.spec.ts) และหน้าตั้งค่าของเจ้าหน้าที่ (settings.spec.ts)
npm run visual       # ถ่ายภาพหน้าจอ แล้วเทียบกับภาพอ้างอิงของงานออกแบบ
```

หมายเหตุ

- `npm run e2e` และ `npm run visual` จะ build เกมและเปิดเซิร์ฟเวอร์ที่พอร์ต 4173 ให้เอง ต้องติดตั้งเบราว์เซอร์ของ Playwright ก่อนหนึ่งครั้งด้วย `npx playwright install chromium`
- `npm run visual` ถ่ายภาพลงโฟลเดอร์ `e2e/screens/` แล้วรัน `tools/compare_screens.py` ด้วย Python ใน `.venv` เพื่อเทียบกับภาพอ้างอิงของงานออกแบบ ภาพอ้างอิงเหล่านี้ไม่อยู่ใน repository จึงรันได้เฉพาะในเครื่องที่มีภาพครบ
- `npm run build` ทำ typecheck ก่อนเสมอ

## ปรับความยาก

แก้ที่ `src/config/gameConfig.ts` ซึ่งแบ่งค่าเป็นสองกลุ่ม

ปรับได้อิสระ

| ค่า | ความหมาย | ค่าปัจจุบัน |
| --- | --- | --- |
| `timeLimitMs` | เวลาต่อรอบ (มิลลิวินาที) | 25000 |
| `mismatchMs` | เวลาที่การ์ดคู่ผิดค้างก่อนคว่ำกลับ | 500 |
| `restartLockMs` | เวลาที่ปุ่ม "เริ่มเกมใหม่" ไม่รับการแตะหลังจบรอบ | 1000 |
| `startLockMs` | เวลาที่ปุ่ม "เริ่มเกม" ไม่รับการแตะหลังรีเซ็ต | 500 |
| `countdownMs` | เวลานับถอยหลังบนฉากดำหลังกด "เริ่มเกม" (แสดงเลขละ 1 วินาที) | 3000 |
| `startCueMs` | เวลาที่คำว่า "เริ่ม!" ค้างก่อนฉากดำหายและเวลาเล่นเริ่มเดิน | 700 |
| `decoyValues` | ตัวเลขหลอก | 84, 88, 44, 80, 40, 41, 81 |

`timeLimitMs`, `mismatchMs`, `countdownMs` และ `startCueMs` ในไฟล์นี้เป็นค่าเริ่มต้น เจ้าหน้าที่ปรับสี่ค่านี้ที่เครื่องบูธเองได้จากหน้าตั้งค่าของเกม และค่าที่บันทึกบนเครื่องจะถูกใช้แทนค่าในไฟล์ (ดูหัวข้อ "ปรับค่าที่เครื่องบูธ" ด้านล่าง)

กฎของค่าที่ปรับได้ (`npm test` ตรวจกฎเหล่านี้ให้)

- `decoyValues` ต้องมี 7 ค่าพอดี ไม่ซ้ำกัน แต่ละค่ายาวสองตัวอักษร และไม่ใช่ `48`
- `timeLimitMs` ต้องเป็นจำนวนวินาทีเต็ม ตั้งแต่ 5 ถึง 99 วินาที (ตัวจับเวลาบนจอแสดงได้สองหลัก และ 5 วินาทีคือค่าต่ำสุดของหน้าตั้งค่า)
- `mismatchMs` ต้องอยู่ระหว่าง 200 ถึง 2000 (ช่วงเดียวกับหน้าตั้งค่า)
- `restartLockMs` และ `startLockMs` ต้องไม่ติดลบ และสั้นกว่าเวลาต่อรอบ
- `countdownMs` ต้องเป็นจำนวนวินาทีเต็ม ตั้งแต่ 0 ถึง 9 วินาที และ `startCueMs` ต้องอยู่ระหว่าง 0 ถึง 2000
- ตั้ง `countdownMs` และ `startCueMs` เป็น 0 ทั้งคู่ เท่ากับปิดการนับถอยหลัง กด "เริ่มเกม" แล้วเวลาเล่นเดินทันที

ชุดทดสอบ (`npm test` และ `npm run e2e`) ยังผ่านเมื่อแก้เฉพาะค่าในกลุ่มนี้ เพราะชุดทดสอบของกติกาใช้ค่าทดสอบของตัวเอง (`src/test/testConfig.ts`) และการทดสอบบนเบราว์เซอร์อ่านเวลาจาก `gameConfig.ts`

ผูกกับงานออกแบบ ห้ามเปลี่ยนโดยไม่แก้ภาพออกแบบด้วย (ขนาดกระดาน จำนวนการ์ด และกรอบรางวัลในภาพถูกวาดตามค่าเหล่านี้)

`targetValue`, `targetPairs`, `decoyPairsEach`, `smallPrizePairs`, `columns`, `rows`

เมื่อแก้แล้ว ให้รัน `npm test` และ `npm run build` แล้วอัปโหลด `dist/` ใหม่ เครื่องที่บูธจะได้รุ่นใหม่เมื่อเปิดเกมครั้งถัดไปขณะมีอินเทอร์เน็ต

### อัปเดตเครื่องที่บูธ

หน้าเกมที่เปิดค้างอยู่ไม่รู้ว่ามีการอัปโหลดรุ่นใหม่ รุ่นใหม่จะเข้ามาเมื่อเปิดเกมครั้งถัดไปขณะมีอินเทอร์เน็ต แล้วหน้าเกมจะโหลดตัวเองใหม่หลังจากนั้นไม่กี่วินาที ซึ่งจะรีเซ็ตรอบที่กำลังเล่นอยู่ ดังนั้น

1. หลังอัปโหลดรุ่นใหม่ ให้เปิดเกมบนเครื่องที่บูธหนึ่งครั้งขณะมีอินเทอร์เน็ต จากทางลัดเดียวกับที่ใช้ที่บูธ
2. รอจนหน้าเกมโหลดตัวเองใหม่เสร็จ ก่อนให้ใครเล่น

**ห้ามอัปโหลดรุ่นใหม่ขณะมีคนกำลังเล่นอยู่กลางรอบ** ควรอัปโหลดตอนไม่มีผู้เล่น

## ปรับค่าที่เครื่องบูธ (หน้าตั้งค่า)

เจ้าหน้าที่ปรับค่าสี่ค่าได้จากหน้าจอเกมที่เครื่องบูธ โดยไม่ต้องแก้โค้ดและไม่ต้องอัปโหลดใหม่ ค่าที่บันทึกมีผลตั้งแต่รอบถัดไป

วิธีเปิด

1. อยู่ที่หน้าเริ่มเกม (เห็นปุ่ม "เริ่มเกม") ระหว่างรอบและตอนมี pop-up ผลการเล่น เปิดไม่ได้
2. กดค้างที่ชื่อ "V Square Clinic" ด้านบนของจอ 3 วินาที
3. ใส่รหัส PIN 4 หลัก ครั้งแรกบนเครื่องนั้น เกมจะให้ตั้งรหัสและใส่ซ้ำเพื่อยืนยัน

ค่าที่ปรับได้

| ค่าในหน้าตั้งค่า | ค่าใน `gameConfig.ts` | ช่วงที่ปรับได้ | ปรับทีละ |
| --- | --- | --- | --- |
| เวลาเล่นต่อรอบ | `timeLimitMs` | 5 ถึง 99 วินาที | 1 วินาที (มีปุ่ม −5 และ +5 ด้วย) |
| นับถอยหลังก่อนเริ่ม | `countdownMs` | 0 ถึง 9 วินาที (0 คือไม่นับถอยหลัง) | 1 วินาที |
| คำว่า "เริ่ม!" ค้าง | `startCueMs` | 0 ถึง 2 วินาที (0 คือไม่แสดง) | 0.1 วินาที |
| คู่ผิดเปิดค้าง | `mismatchMs` | 0.2 ถึง 2 วินาที | 0.1 วินาที |

ค่าอื่นใน `gameConfig.ts` ปรับจากหน้านี้ไม่ได้ ช่วงและขั้นของแต่ละค่าอยู่ใน `src/settings/settings.ts`

สิ่งที่ควรรู้

- ค่าและรหัส PIN เก็บในเบราว์เซอร์ของเครื่องนั้นเท่านั้น (localStorage) ไม่มีเซิร์ฟเวอร์ และไม่อยู่ใน repository นี้ ถ้ามีหลายเครื่องต้องตั้งทีละเครื่อง
- ค่าที่บันทึกบนเครื่องถูกใช้แทนค่าใน `gameConfig.ts` เครื่องที่เคยบันทึกค่าไว้จึงไม่เปลี่ยนตามรุ่นใหม่ที่อัปโหลด จนกว่าจะกด "คืนค่าเริ่มต้น" แล้ว "บันทึก" ที่เครื่องนั้น ซึ่งจะลบค่าที่เก็บไว้ แล้วเครื่องจะกลับไปใช้ค่าของรุ่นที่ build
- ค่าและรหัสผูกกับที่อยู่เว็บของเกม (origin) ถ้าย้ายเกมไปโดเมนอื่น เครื่องจะเริ่มจากค่าของรุ่นที่ build และยังไม่มีรหัส
- การกดค้างต้องใช้นิ้วเดียว ถ้าเลื่อนนิ้วออกนอกชื่อ หรือมีนิ้วอื่นแตะจอระหว่างนั้น การกดค้างจะถูกยกเลิก
- หน้าตั้งค่าปิดเองเมื่อไม่มีใครแตะ 30 วินาที โดยไม่บันทึก และปิดเมื่อใส่รหัสผิดครบ 3 ครั้ง
- รหัส PIN มีไว้กันผู้เล่นและคนเดินผ่าน ไม่ใช่ระบบรักษาความปลอดภัย คนที่ต่อคีย์บอร์ดแล้วเปิดเครื่องมือของเบราว์เซอร์ได้ ย่อมอ่านและแก้ค่าได้
- วิธีเปิดเกมแบบ ค ในคู่มือตั้งค่าเครื่อง (Edge โหมด kiosk) เป็นหน้าต่าง InPrivate จึงลืมทั้งค่าและรหัสทุกครั้งที่ปิดเกม
- การตั้งรหัสตอนติดตั้งเครื่อง และวิธีแก้เมื่อลืมรหัส อยู่ใน[หัวข้อที่ 8 ของคู่มือตั้งค่าเครื่อง](docs/kiosk-setup-windows.md)

## ดึงภาพใหม่เมื่อไฟล์ออกแบบเปลี่ยน

ภาพในเกมสร้างจากไฟล์ PSD ของนักออกแบบด้วย `tools/extract_assets.py` ไฟล์ PSD ไม่อยู่ใน repository ให้ขอจากเจ้าของงานแล้ววางไว้ที่รากโปรเจกต์ (ไฟล์ `*.psd` ถูกกันไว้ใน `.gitignore`) จากนั้นติดตั้งแพ็กเกจของ Python หนึ่งครั้ง แล้วรันสคริปต์

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r tools/requirements.txt
.venv/Scripts/python tools/extract_assets.py
```

## นำขึ้นใช้งาน

1. รัน `npm run build`
2. อัปโหลดเนื้อหาข้างในโฟลเดอร์ `dist/` ทั้งหมดไปยังโฮสต์ที่เป็น **HTTPS** (HTTPS จำเป็นต่อการทำงานแบบออฟไลน์และการกันจอดับ) จะวางที่รากของโดเมนหรือในโฟลเดอร์ย่อยก็ได้ เพราะใช้พาธแบบสัมพัทธ์
3. ส่งลิงก์ให้เจ้าหน้าที่บูธในรูปที่ลงท้ายด้วย `/` (เช่น `https://example.com/game/`) หรือลงท้ายด้วย `index.html` (เช่น `https://example.com/game/index.html`) ห้ามใช้ลิงก์โฟลเดอร์ที่ไม่มี `/` ท้าย (`https://example.com/game`) เพราะลิงก์แบบนั้นอยู่นอกขอบเขตของแคชออฟไลน์ เกมจะเปิดไม่ได้ตอนไม่มีอินเทอร์เน็ต

**ห้าม commit `dist/` หรือ `fonts/` ขึ้น repository ใด ๆ** และห้ามใช้โฮสต์ที่ต้องนำไฟล์เหล่านี้ขึ้น repository เช่น GitHub Pages หรือบริการที่ build เกมจาก repository เอง เพราะไฟล์ที่ build แล้วมีฟอนต์ Gotham ที่มีลิขสิทธิ์รวมอยู่ด้วย

## ตรวจหลังนำขึ้นใช้งาน

1. เปิดลิงก์ของเกมใน Microsoft Edge ตรวจว่าเห็นกระดาน และตัวเลขเป็นฟอนต์ Gotham
2. กด F12 เปิด DevTools ไปที่ Application > Service workers ตรวจว่ามีสถานะ activated
3. ปิดอินเทอร์เน็ตของเครื่อง โหลดหน้าใหม่ แล้วเล่นให้ครบหนึ่งรอบ
